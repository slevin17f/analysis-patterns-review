# 类型模型的实现契约

## R · 原书依据

§14.1–14.7。将类型图展开为读写、创建和销毁契约，核对每条关联的不变量。

## I · 如何选择

将类型图展开为读写、创建和销毁契约，核对每条关联的不变量。
- 按访问需要选单向指针、双向指针或查找；对动态分类比较标志、委派等；创建时提供必需且不可变值；明确销毁级联与查找入口；为约束安排检查。

## A1 · 原书建模示例

客户可以改变优先级身份（§14.2.3，第 283 页，图 14.6）。普通客户可升为优先客户；标志字段实现动态分类，但此前只有子类型具备的操作现在都能在客户对象上被调用。查询专属代表时须先检查是否为优先客户；普通客户调用应报告错误，不能读取无意义的代表。

## A2 · 何时调用

动态分类 / 双向关联 / 构造的建模或评审。语言线索包括 动态分类 双向关联 构造 销毁 约束。相关但输出不同的任务见「带属性、键和历史的关联」。

## E · 执行与验收

输入需要关系的读写方向、分类可变性、创建与销毁规则。

1. 按访问需要选单向指针、双向指针或查找。
2. 对动态分类比较标志、委派等。
3. 创建时提供必需且不可变值。
4. 明确销毁级联与查找入口。
5. 为约束安排检查。

按项目涉及的分支检查：

- 对象变更雇主时，旧反向集合删除、新反向集合加入、前向指针更新；同时检验两端。
- 列出依赖对象的强制关联；选择拒绝删除、转移或连带销毁的具体业务策略，检验无悬空关系。

输出应包含接口、维护方和不变量表。
将优先客户降为普通客户，沿原有订单引用取客户，核对身份。双向换雇主后从新旧两端读取。

## B · 反例与判停

- 用标志实现分类却放行所有子类型操作。子类行为现在出现在共同接口上，调用非优先客户的专属代表将产生无意义结果；须检查适用类别。（§14.2.3，书页 283）
- 实现取决于目标语言和更新频率。
