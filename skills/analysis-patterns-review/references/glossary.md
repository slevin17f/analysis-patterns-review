# 《Analysis Patterns》建模词典

以下释义为中文转述。编号对应原书章节。评审时可用最右栏的问题检查某个词在项目里指向规则、实例，还是一次具体事件。

## 关系与知识层

| 术语及出处 | 业务含义 | 评审时核对 |
|---|---|---|
| 主体与岗位（Party / Post） · §2.1、2.9 | 责任关系的参与端可为人、组织或岗位；岗位持续承载随任职移交的职责。同一岗位可先后由不同的人担任。 | 换岗测试中分别查岗位和任职者。 |
| 责任关系（Accountability） · §2.4–2.5 | 一方就一项有类型的责任向另一方负责。responsible party 是承担方，commissioner 是承担方向其负责的一方。 | 记录两个端点及其方向，再作约束。 |
| 知识层与运作层（Knowledge / Operational Level） · §2.5、3.11 | 知识层描述哪些类型、取值或联系被允许；运作层记录实际发生的实例。“口渴可能提示糖尿病”与“这次诊断参考了该患者的这次口渴观察”有各自的记录。 | 把领域规则与发生事实分别测试。 |

## 观察与指标

| 术语及出处 | 业务含义 | 评审时核对 |
|---|---|---|
| 现象与现象类型（Phenomenon / Phenomenon Type） · §3.4–3.6 | 类型给出观察的性质，如血型；现象给出相应定性取值，如 A 型。一条具体观察把某个对象和该取值联系起来。 | 核查结果是否属于该观察项目允许的集合。 |
| 量与测量（Quantity / Measurement） · §3.1–3.5 | 量由数值和单位构成；测量把对象、被测性质和一个量联系起来。两次测量可有相同的量，仍是两项业务记录。 | 跟踪测量历史时为观察保留独立身份。 |
| 测量协议（Measurement Protocol） · §3.7、4.2 | 协议描述获得观察结果的方法；企业指标可通过源系统取得或由公式计算。同一指标可有多个适用协议。 | 比较数值之前先检查协议与单位。 |
| 双时间记录（Dual Time Record） · §3.8 | 分别表示观察何时适用、何时被记录；两者都可采用时点或时段。“昨日起出现，今日才登记”提供两个独立时间。 | 分别回答当时情形和当时可知情况。 |
| 被驳回的观察（Rejected Observation） · §3.9 | 事后发现原来就不成立的观察仍被保存，并指明否定它的观察。骨折后来愈合只需结束适用期。 | 更正时能重建早先行动所依据的记录。 |
| 企业分部（Enterprise Segment） · §4.1 | 从每个分析维度选一个元素形成的组合，元素可以是层级顶部的全体。一个分部可以同时限定地区、产品与客户类别。 | 核对汇总及比较的实际覆盖范围。 |

## 身份与记账

| 术语及出处 | 业务含义 | 评审时核对 |
|---|---|---|
| 标识体系（Identification Scheme） · §5.2 | 在指定体系内，标识字符串解析到一个对象。同一个对象可有别名，两个体系可使用同一字符串。 | 把体系纳入唯一键并核实业务是否允许别名。 |
| 合并与等价（Object Merge / Object Equivalence） · §5.3–5.4 | 合并处理同一实体的多个记录；等价表达在特定观点下可同等看待的对象。两个临床术语在一种分类下对应，另一种分类可继续区分。 | 要求提供同一性依据或等价作用范围。 |
| 分录与交易（Entry / Transaction） · §6.1–6.2 | 分录表达一个账户上的数量变化；交易将属于同一次转移的分录合在一起。交易边界容纳多条分录；余额可从分录导出。 | 用成组分录检验数量是否守恒。 |
| 入账规则与核算惯例（Posting Rule / Accounting Practice） · §6.5、6.7、6.10–6.11 | 入账规则说明如何根据来源生成新账项；核算惯例把应共同采用的一组规则组织起来。同一套结构可因客户采用的规则集而计算不同费用。 | 为生成项保留规则及源分录。 |

## 计划与交易

| 术语及出处 | 业务含义 | 评审时核对 |
|---|---|---|
| 提议动作与实施动作（Proposed / Implemented Action） · §8.1–8.2 | 提议表达意图；开始实施会产生独立的实施记录，保留实际发生的差异。行动可以临时实施，也可能提议后被放弃。 | 检查偏离计划能否留下历史。 |
| 行动协议与计划（Protocol / Plan） · §8.4–8.5 | 协议描述可重复采用的做法；一个计划组织本次的提议动作及依赖。计划可引用实际对象与安排；协议可简至名称或操作说明。 | 区分标准步骤、个案安排与实际执行。 |
| 组合（Portfolio） · §9.2 | 一组为某一用途共同考察的合同，可按条件筛选。同一合同能否入多个组合取决于组合的用途和定义。 | 在计算组合总量前明确重叠语义。 |
| 情景（Scenario） · §9.4 | 一组真实或假设的市场状态，按输入和推导规则提供各工具的行情。同一合同在不同情景下估值，其成交事实仍保留。 | 分清成交条件与估值输入。 |
| 产品与合同（Product / Contract） · §9.1、10.3 | 在组合交易案例中，销售把若干风险管理合同包装为一个对客产品。销售的交易单位和内部估值单位可以不同。 | 避免对组合和组成合同重复计数。 |

## 实现与关联

| 术语及出处 | 业务含义 | 评审时核对 |
|---|---|---|
| 包可见性（Package Visibility） · §11.1–11.3、附录 A.5 | 一个包能够直接使用另一个包暴露的类型。通过中间包形成的前置依赖未必具有直接可见性。 | 区别直接引用和部署依赖。 |
| 应用门面（Application Facade） · §12.3、13.1–13.6 | 为特定展示任务提供可用的属性和操作，在应用逻辑中协调领域对象。同一任务可有多个展示；跨任务通用的领域规则应放到领域对象。 | 脱离具体界面仍可执行用例。 |
| 设计模板（Design Template） · 第 14 章，pp.271–274 | 约定同类概念构造应映射为何种软件接口，以及有哪些实现可选。一种关联接口可使用不同存储与导航手段。 | 将概念模型的实现约束写成团队可复查的约定。 |
| 历史映射（Historic Mapping） · §15.3 | 为一个映射保存不同时期适用的值，以日期选出对应值。记录生效区间只回答有效历史；回放录入历史还要求独立记录时间。 | 在变更日检验边界与多重性。 |
