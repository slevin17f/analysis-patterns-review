# 《Analysis Patterns》整书理解

Martin Fowler，《Analysis Patterns: Reusable Object Models》，Addison-Wesley。来源为用户提供的 1996 年版 PDF（361 个 PDF 页面）。以下定位使用章节号和书内印刷页码。

**主旨**　在具体业务中找出反复出现的对象关系，用真实实例检验这些关系能否迁移，再为选定的模型设计软件接口。

## 论证与证据

1. 第 1 章从领域专家能讨论的概念模型出发。复用时需要知道某个结构解决过什么问题，以及哪些变化会使原来的取舍失效。
2. 第 2–5 章并列处理组织、观察与身份，再演示跨域迁移。医院里描述“如何测得”的协议，到了企业指标分析中仍有意义，但还需说明统计的是哪个地区、产品与渠道的组合。
3. 第 6–8 章区分记录与驱动记录的规则。一次通话产生用量，引发计费和计税；可追溯的分录把业务事件与金额变化连起来。计划领域也需要同时保留原定动作与实际执行。
4. 第 9–11 章以交易系统展示模型如何随产品与用例增长。合同约定、报价和情景假设各自承载不同事实。新产品还会改变状态和包依赖，不能仅靠增加字段解决。
5. 第 12–15 章从概念转向软件设计。先分配界面、应用、领域和存储职责，再处理关联、分类与约束的实现。第 16 章收束；附录 A 解释记号，附录 B 提供模式索引。

## 建模时容易混淆的词

| 术语 | 在模型中负责什么 |
|---|---|
| Party / Post | 人和组织均可作为关系的参与方；岗位让职责在任职者更替后仍可延续。 |
| Accountability / Accountability Type | 一条具体责任关系连接责任方与委托方；类型描述该种关系，并可约束允许参与的主体类型。 |
| Phenomenon Type / Observation | 前者说明观察哪个性质；后者记录特定对象在特定情境中的观察结果。 |
| Measurement Protocol | 说明得到指标的方法，同名指标能否比较取决于其计算或观察口径。 |
| Identification Scheme | 指明标识符在哪套体系中解释。跨体系比较字符串不足以认定同一对象。 |
| Entry / Transaction / Posting Rule | 分录改变账户，交易将相关分录组成整体，入账规则描述如何由来源生成后续分录。 |
| Plan / Protocol | 计划组织为某次执行提出的动作，协议保存可反复实例化的做法。 |
| Application Facade | 向某类应用任务提供接口，把展示所需的操作与领域模型的内部结构隔开。 |

|---|---|---|---|
| T01 | 选择组织树、具名关系或可配置责任类型 | §2.1–2.9，图 2.9 | 用两种关系或一次换岗验证关系图；防止通用关系吞掉业务约束。 |
| T02 | 表示定量、定性、修订和预测 | §3.1–3.12 | 给出单位、方法、适用时刻与记录时刻；检验事后更正能否还原当时所知。 |
| T03 | 定义可比较的企业指标 | §4.1–4.5，图 4.2 | 给出分部维度和计算协议，防止把范围不同的数值直接汇总。 |
| T04 | 处理同一对象的重复记录，以及不同对象在特定语境下的等价 | §5.1–5.4 | 以重复患者档案检验合并后的引用，以两套临床术语检验等价的适用范围。 |
| T05 | 记录流量并从来源推导账项 | §6.1–6.15，第 7 章通话例 | 画出一笔交易的分录和规则依赖，核对平衡、税费来源与执行时点。 |

| T07 | 区分交易、组合、行情和情景 | §9.1–9.4 | 用同一合约在两个情景下生成两份估值输入，保留原成交条件。 |
| T08 | 扩展合约类型及其生命周期 | §10.1–10.5 | 比较两种期权表示方式，用行权事件检验合同与产品定义的职责。 |
| T09 | 定义交易模块可见性 | §11.1–11.4 | 画依赖方向并验证新增产品时受影响的包。 |
| T10 | 划分层次并设计应用门面 | §12.1–13.6 | 将同一操作走通两个展示入口，判断业务规则归属及输入转换位置。 |
| T11 | 把类型图转换为实现约定 | §14.1–14.7 | 给出关联维护、动态分类、创建销毁与约束检查的示例契约。 |
| T12 | 为带属性、按键或带历史的关联建模 | §15.1–15.3 | 用指定键、指定日期查询一次关系，校验多重性与历史有效期。 |

## 适用边界与拟议交付

优先用真实项目需求评审候选模型。先用一组实例和一个反例说明最简单结构何时失效，再考虑规则对象或知识层。作者的案例来自具体项目，跨域类比仍须领域专家核验。书中的 Smalltalk 示例和客户端/服务器部署反映当时的实现环境；分布式一致性、当代监管口径与实际估值数据须另取依据。

建议编译为一个中文入口，按上述任务调用能力卡。优先验证身份、双时间记录、分录追溯和职责建模，再检查金融与架构专题的可达性。附录记号和模式表用作查找依据。能力数量待来源核验及任务测试后确定。
